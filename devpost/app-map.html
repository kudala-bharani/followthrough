A three-stop reference route

This is a reference route, not a record of a completed hands-on tour.

  1. src/app.mjs → applyRecord
    The button finds an application by ID. It requests an updated record, then applies it only when saving succeeds.
  2. src/model.mjs → logFollowUp, daysWaiting, isDue
    A follow-up records today's local date. Calendar components become day numbers, so a daylight-saving clock change does not move the seven-day boundary.
  3. src/storage.mjs → save and src/app.mjs → render
    The complete list is validated and saved. The queue then excludes this application until its fresh seven-day wait ends. Failed writes leave the prior in-memory list intact.

To change this, start here

  • Wording and page structure: index.html; generated card wording: src/app.mjs → card
  • Colors, spacing, and narrow screens: styles.css → :root and its media query
  • Date or status rules: src/model.mjs, then the matching test/model.test.mjs cases; changing the seven-day rule is a product decision
  • Import safeguards: validateEnvelope and the import handlers in src/app.mjs

A practice to reuse

Turn a fuzzy phrase into a boundary you can observe. devpost/prd.md → Explainable Follow-up Queue defines “seven or more calendar days.” The test queue has precise six, seven, and eight day boundaries checks both sides of that threshold. On another project, write an example just before, exactly at, and just after an important cutoff before relying on the implementation.
